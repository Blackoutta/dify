# Phoenix Loop Index Wrapper Spans 开发日记

## Feature 目的

这个 feature 解决 Phoenix trace tree 中 loop/iteration body 节点过于扁平的问题。Dify workflow 在 loop 或 iteration 中重复执行同一批 body 节点时，原先所有子节点都直接挂在 loop/iteration container span 下，Phoenix 里很难按第几次执行来阅读。

目标是在 Phoenix/Arize exporter 内增加 display-only synthetic wrapper spans，例如 `loop[0]`、`loop[1]`、`iteration[0]`。这些 wrapper 只服务于 trace 展示分组，不改变 Dify workflow runtime、数据库 schema、API 响应，也不改变 nested workflow 通过 tool span 发布 parent carrier 的语义。

## 实现与迭代过程

最初先明确 wrapper span 是展示分组，不是新的业务执行节点。因此实现被限制在 `api/core/ops/arize_phoenix_trace/arize_phoenix_trace.py`，没有改 runtime 事件、workflow node execution 持久化结构或 Phoenix UI。

设计阶段确认了几个约束：

- wrapper 只在 metadata 同时包含有效 container id 和有效 index 时创建。
- `loop_index` / `iteration_index` 的合法值需要稳定，避免把空字符串、布尔值、浮点数或含特殊字符的字符串变成 span 名。
- wrapper 必须挂在真实 loop/iteration container span 下，body 节点再挂到 wrapper 下。
- tool node 仍然从 tool span 本身发布 carrier，child workflow 继续挂在 tool span 下，而不是 synthetic wrapper 下。

实现采用分阶段 TDD：

1. 先加入 `_normalize_wrapper_index()`，把 index 合法性收敛到一个小的 helper。
2. 再加入 `_build_wrapper_groups()`，预先从 workflow node execution metadata 计算 wrapper group、child membership、时间边界和错误状态。
3. 在 `workflow_trace()` 中接入 wrapper emission，并处理无 index、非法 index、container graph id 歧义时的 fallback。
4. 增加 iteration wrapper 覆盖、child query attributes、tool carrier preservation 断言。
5. 补 wrapper start/end/status 聚合测试。

过程中有两次重要修正：

- wrapper span 最初只在 node emission 正常结束后统一 end。code review 指出如果 child node export 中途抛错，已经创建的 wrapper 可能不会关闭。后续把 wrapper finalization 放进 `finally`，并用 `finalized_wrapper_keys` 做幂等保护。
- iteration container span 一度为了测试期望被命名成 `iteration_Iteration`。这会改变已有 observability surface，可能影响 Phoenix filters 或 dashboards。后续回退该生产行为，保留原有 container span name `iteration`，wrapper 仍命名为 `iteration[0]` 等。

## 本地 Feature 测试覆盖点

测试集中在 `api/tests/unit_tests/core/ops/test_arize_phoenix_trace.py`：

- wrapper index normalization：接受非负整数和稳定字符串，拒绝布尔值、负整数、浮点数、空字符串、空白包裹字符串和含不稳定字符的字符串。
- wrapper group precompute：按 `loop_id + loop_index` 分组，并在 container graph id 歧义时不创建 wrapper。
- loop body grouping：同一 loop 下不同 `loop_index` 的 body 节点分别挂到 `loop[0]`、`loop[1]`、`loop[2]`。
- fallback 行为：无 index、非法 index、container graph id 歧义时保持原有 parent 行为。
- iteration grouping：iteration container 下创建 `iteration[0]`、`iteration[1]` wrapper，body 节点挂到对应 wrapper。
- child node query attributes：带出 `dify.node.loop_index` 和 `dify.node.iteration_index`。
- wrapper metadata/query attributes：包含 synthetic 标记、wrapper type/index、container execution id。
- carrier preservation：tool node 在 wrapper 下时，parent carrier 仍从 tool span context 注入并发布。
- wrapper lifecycle：child export 抛错时 wrapper 仍会 end，且只 end 一次。
- wrapper bounds/status：wrapper start/end 来自 child min/max 时间，status 在任一 child 失败时为 error。
